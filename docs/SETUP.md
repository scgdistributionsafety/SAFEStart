# คู่มือติดตั้ง SafeStart v2 (Phase 1)

ใช้เวลาประมาณ 1–2 ชั่วโมง ทำครั้งเดียว · ทุกบริการใช้แพ็กเกจฟรี และสมัครด้วย **บัญชีกลางของทีม** (ไม่ใช้บัญชีส่วนตัว)

| บริการ | ใช้ทำอะไร | จำเป็นไหม |
|---|---|---|
| Supabase | ฐานข้อมูล ระบบเข้าสู่ระบบ ที่เก็บรูป | จำเป็น |
| GitHub Pages | วางหน้าเว็บ | จำเป็น |
| Google Apps Script | งานอัตโนมัติ ส่งต่อเรื่อง ส่ง LINE/อีเมล สรุปเที่ยง | จำเป็น |
| LINE Official Account | แจ้งเรื่องที่ต้องรับทราบและเรื่องด่วน | แนะนำ |
| Supabase Edge Function | แจ้งเตือนบนมือถือ (ฟรี ไม่จำกัด) | แนะนำ |

---

## ขั้นที่ 1 · ฐานข้อมูล (Supabase)

1. สมัคร https://supabase.com → **New project** → Region **Southeast Asia (Singapore)** → ตั้งรหัสฐานข้อมูลแล้วจดไว้
2. เปิด **SQL Editor** แล้วรันทีละไฟล์ (เปิดไฟล์ → คัดลอกทั้งหมด → วาง → **Run**)
   - **ถ้าเคยติดตั้งรุ่นแรกไว้แล้ว:** รัน `supabase/reset.sql` ก่อน (ข้อมูลเดิมหายทั้งหมด บัญชีผู้ใช้ยังอยู่)
   - รัน `supabase/schema.sql` (ต้องขึ้น Success. No rows returned)
   - เปิด `supabase/seed.sql` แก้ `CHANGE_ME@scg.com` เป็นอีเมลของคุณ **ระวังให้มีเครื่องหมาย `'` ครบทั้งหน้าและหลัง** เช่น `'CHANGE_ME@scg.com'` แล้วรัน
3. ตรวจ: เมนู **Table Editor** ต้องมีตาราง `scg_companies` 2 แถว (SCG Distribution, SCG Home Experience) และ `job_types` 26 แถว · เมนู **Storage** ต้องมี bucket `photos` `idcheck` `health`
4. **Authentication › Sign In / Providers › Email** เปิด Email และตั้ง *Email OTP Length* = 6
5. **Authentication › Emails › Templates › Magic Link** แก้ข้อความให้มีรหัส เช่น

   ```
   <h2>รหัสเข้าสู่ระบบ SafeStart</h2>
   <p>รหัสของคุณคือ <b>{{ .Token }}</b> (ใช้ได้ 1 ชั่วโมง)</p>
   <p>หรือกดลิงก์นี้: <a href="{{ .ConfirmationURL }}">เข้าสู่ระบบ</a></p>
   ```
6. **ส่งอีเมลได้มากพอ (สำคัญเมื่อใช้กับผู้รับเหมาทุกราย):** อีเมลในตัวของ Supabase ส่งได้แค่ไม่กี่ฉบับต่อชั่วโมง ให้ตั้ง **Authentication › Emails › SMTP Settings** ด้วยบัญชี Gmail ของทีม (เปิด 2-Step แล้วสร้าง App password · Host `smtp.gmail.com` · Port `465`) หรือบริการส่งอีเมลฟรีอื่น
7. จด **Project Settings › API**: `Project URL` และ `anon public` key (ใช้ขั้นที่ 2) · `service_role` key (ใช้ขั้นที่ 4 เท่านั้น **ห้ามใส่ในหน้าเว็บ**)

## ขั้นที่ 2 · หน้าเว็บ (GitHub Pages)

1. แก้ `web/config.js` ใส่ `SUPABASE_URL` และ `SUPABASE_ANON_KEY`
2. สร้าง repository ใหม่ใน GitHub (เช่น `safestart`) → **Add file › Upload files** → ลากไฟล์ทั้งหมดในโฟลเดอร์ `web/` (รวมโฟลเดอร์ `tools`) → Commit
3. **Settings › Pages** → Source: *Deploy from a branch* → Branch `main` / root → Save · รอ 1–2 นาทีจะได้ลิงก์ เช่น `https://ทีม.github.io/safestart/`
4. กลับไป Supabase **Authentication › URL Configuration** ใส่ลิงก์นี้ใน *Site URL* และ *Redirect URLs*

## ขั้นที่ 3 · เข้าใช้ครั้งแรกและตั้งค่า

1. เปิดลิงก์ → **พนักงาน SCG** → ใส่อีเมลที่ใส่ไว้ใน seed → ใส่รหัส 6 หลัก → ยินยอม PDPA
2. คุณจะเป็น **SCG Safety (Admin) ของทั้ง 2 บริษัท** และเป็นผู้ดูแลระบบ (เพิ่มบริษัท SCG ได้ในตั้งค่า › บริษัท SCG)
3. ตั้งค่าของแต่ละบริษัท (เลือกบริษัทจากแถบสีใต้หัวจอ)
   - **ตั้งค่า › ผู้ใช้** เชิญ IC, IC & QC Manager, Purchasing, M&S Manager/Director, ผู้บริหาร (ถ้าแต่ละบริษัทมี Safety ของตัวเอง ให้เชิญเป็น SCG Safety ของบริษัทนั้น)
   - **ตั้งค่า › กติกา/อากาศ** ตรวจค่า SLA รัศมี check-in เกณฑ์ลมและดัชนีความร้อน
   - **ตั้งค่า › ประเภทงาน** ตรวจกลุ่มอันตรายของแต่ละประเภทงาน
4. **ผู้รับเหมา** (Purchasing หรือ Safety): ค้นด้วยเลขผู้เสียภาษี 13 หลัก → ลงทะเบียน ใส่รหัส Vendor ที่ใช้ในไฟล์ PO → ใส่อีเมลผู้ดูแลบริษัทผู้รับเหมาเพื่อเชิญ
5. **แผนงาน/PO › นำเข้า PO จาก Excel**: เลือกไฟล์ PO แบบเดิมของบริษัท → จับคู่คอลัมน์ครั้งแรก (ระบบจำไว้) → นำเข้า · โครงการใหม่ถูกสร้างให้อัตโนมัติ แล้วไปใส่ IC และโรงพยาบาลใน **ตั้งค่า › โครงการ**
6. ส่งลิงก์ให้ผู้ดูแลบริษัทผู้รับเหมา: เข้าด้วยอีเมลที่เชิญ → เพิ่มช่าง (แนบรูปบัตรชั่วคราว) → ทำ Self-declaration ของช่างที่ขึ้นที่สูง → เพิ่ม cert → สร้างทีม → เชิญหัวหน้าทีม (บัญชีรายคน)
7. Purchasing ตรวจตัวบุคคลและอนุมัติช่าง · รับรอง cert ในกล่องงาน

## ขั้นที่ 4 · งานอัตโนมัติ (Google Apps Script)

1. https://script.google.com → **New project** → ตั้งชื่อ SafeStart → วางโค้ดจาก `apps-script/Code.gs` แทนของเดิม → Save
2. **Project Settings › Script properties** เพิ่ม
   | Property | ค่า |
   |---|---|
   | `SUPABASE_URL` | Project URL |
   | `SUPABASE_SERVICE_KEY` | service_role key |
   | `APP_URL` | ลิงก์ GitHub Pages |
   | `LINE_TOKEN` | Channel access token (ขั้นที่ 5 · ยังไม่มีเว้นไว้) |
   | `PUSH_URL` / `PUSH_SECRET` | ขั้นที่ 6 (ยังไม่มีเว้นไว้) |
3. เลือกฟังก์ชัน `testConnection` → **Run** → อนุญาตสิทธิ์ → Log ต้องขึ้นชื่อ 2 บริษัท
4. เลือก `setupTriggers` → **Run** (ตั้งเวลาทุก 5 นาที / 07:00 / ทุก 30 นาทีช่วงเช้า / 12:00 / 18:30)

## ขั้นที่ 5 · LINE OA (แนะนำ)

1. สร้าง LINE Official Account → เปิด **Messaging API** → ใน LINE Developers ออก **Channel access token (long-lived)** → ใส่ใน `LINE_TOKEN`
2. ใน Apps Script: **Deploy › New deployment › Web app** · Execute as: *Me* · Who has access: *Anyone* → คัดลอก URL
3. LINE Developers › Messaging API › **Webhook URL** = URL จากข้อ 2 → เปิด *Use webhook* · ปิด *Auto-reply messages*
4. ผู้ใช้แต่ละคน: เพิ่มเพื่อน LINE OA → ในแอปหน้า **ฉัน** กด "ขอรหัสผูก LINE" → พิมพ์รหัสในแชต
5. แพ็กเกจฟรีส่งได้ 300 ข้อความ/เดือน ระบบส่ง LINE เฉพาะเรื่องที่ต้องรับทราบและเรื่องด่วน ถ้าเกินให้อัปเป็น LINE OA Basic

## ขั้นที่ 6 · แจ้งเตือนบนมือถือ (แนะนำ · ฟรี)

1. เปิด `https://ลิงก์ของคุณ/tools/vapid.html` → กด **สร้างกุญแจ**
2. ใส่ *Public key* ใน `web/config.js` (VAPID_PUBLIC_KEY) แล้วอัปโหลดขึ้น GitHub ใหม่
3. Supabase › **Edge Functions › Deploy a new function › Via Editor** → ชื่อ `push` → วางโค้ด `edge/push/index.ts` → Deploy
4. Edge Functions › **Secrets** เพิ่ม `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (เช่น `mailto:อีเมลทีม`), `PUSH_SECRET` (ตั้งคำยาว ๆ เอง)
5. Apps Script: `PUSH_URL` = `https://<project>.supabase.co/functions/v1/push` · `PUSH_SECRET` = ค่าเดียวกับข้อ 4
6. ผู้ใช้กด **ฉัน › เปิดแจ้งเตือนบนเครื่องนี้** (iPhone ต้องติดตั้งแอปบนหน้าจอโฮมก่อน)

## เช็กลิสต์ทดสอบก่อนใช้จริง

1. หน้าแรก 2 ปุ่ม → เข้าสู่ระบบด้วยรหัส 6 หลัก → หน้ายินยอม PDPA ขึ้นครั้งแรกครั้งเดียว
2. ผู้ใช้ที่มีหลายบริษัทเห็นหน้าเลือกบริษัท และสลับได้จากแถบสีใต้หัวจอ · ปุ่มย้อนกลับของมือถือปิดหน้าซ้อนทีละชั้น
3. ผู้รับเหมาเพิ่มช่าง → Purchasing ตรวจบัตร (รูปบัตรหายจากระบบหลังตรวจ เหลือเลขท้าย 4 หลัก) → อนุมัติ → ช่างใช้ได้เฉพาะบริษัทที่อนุมัติ
4. ยื่นแผนงานเสี่ยงต่ำ = อนุมัติทันที · เสี่ยงกลาง = ผู้ดูแลบริษัทอนุมัติ IC ได้แจ้ง · เสี่ยงสูง = เข้ากล่องงาน IC
5. งานที่สูงตอบ "ไม่มีจุดยึด" ยื่นแผนไม่ได้
6. Check-in งานที่สูง: ช่างขาด cert/Self-declaration เลือกขึ้นที่สูงไม่ได้ · ความดันเกินเกณฑ์ขึ้นไม่ได้ · ขึ้นคนเดียวไม่ได้ (Buddy) · ข้อ ★ ไม่ผ่านต้องแก้ก่อน
7. ได้บัตรส้ม → ส่งรูปจุดยึด/ทางเดิน → บัตรเขียว · ปล่อยเกิน 60 นาที IC ได้แจ้งเตือน
8. IC สแกน QR บัตรผ่านจากเมนูสแกน เห็นรายชื่อ · สแกนด้วยกล้องมือถือโดยไม่เข้าระบบเห็นแค่ "ใช้ได้/ใช้ไม่ได้"
9. ผู้รับเหมากด SOS ค้าง 1 วินาที → IC/Safety/ผู้ดูแลบริษัทได้แจ้งด่วน (แอป + LINE + อีเมล) ซ้ำทุก 5 นาทีจนกดรับทราบ
10. IC สั่งหยุดงาน (LSR) → บัตรผ่านใช้ไม่ได้ทันที check-in ไม่ได้จนปลดล็อก · Safety บันทึกโทษ → ช่างถูกห้ามทำงานเฉพาะบริษัทนั้น บริษัทอื่นเห็น Flag
11. ไม่ปิดงานวันนี้ → พรุ่งนี้ check-in ไม่ได้ · 18:30 มีแจ้งเตือนให้ปิดงาน
12. ไม่กดรับทราบภายใน 4 ชม. (ด่วน 30 นาที) → ส่งต่อขั้นถัดไปอัตโนมัติ

## ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| รันไฟล์ SQL แล้วขึ้น `syntax error at or near "@"` | อีเมลใน seed ขาดเครื่องหมาย `'` |
| รัน schema แล้วขึ้น `relation ... already exists` | เคยติดตั้งแล้ว ให้รัน `reset.sql` ก่อน |
| เข้าระบบแล้วขึ้น "บัญชียังไม่ได้รับสิทธิ์" | อีเมลยังไม่มีคำเชิญ ให้คนที่มีสิทธิ์เชิญก่อน แล้วเข้าระบบใหม่ |
| ไม่ได้รับอีเมลรหัส | ตั้ง SMTP (ขั้นที่ 1 ข้อ 6) และดูโฟลเดอร์สแปม |
| หน้าเว็บขึ้น "ยังไม่ได้ตั้งค่า" | ยังไม่ได้แก้ `config.js` |
| รูปเก่ากว่า 60 วันยังอยู่ | การย้ายรูปไป Google Drive อัตโนมัติอยู่ใน Phase 2 · แพ็กเกจฟรีเก็บรูปได้ 1 GB |

## สิทธิ์ที่ระบบบังคับในฐานข้อมูล (แก้หน้าเว็บก็เลี่ยงไม่ได้)
- พนักงาน SCG เห็นเฉพาะข้อมูลบริษัทตัวเอง · ผู้รับเหมาเห็นเฉพาะบริษัทตัวเอง
- บทบาทมาจากคำเชิญเท่านั้น · ผู้รับเหมาแก้สถานะช่าง ผลตรวจตัวบุคคล หรือ Self-declaration เองไม่ได้
- ค่าตรวจสุขภาพเห็นเฉพาะผู้ดูแลบริษัทผู้รับเหมาและ SCG Safety · คำตอบ Self-declaration เห็นเฉพาะผู้ดูแลบริษัทผู้รับเหมา
- service_role key อยู่ใน Apps Script ที่เดียว
